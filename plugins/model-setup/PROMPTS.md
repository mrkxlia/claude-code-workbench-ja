## 0. 初回プロンプトテンプレート（Plan モード用）

Plan モードの最初の依頼に貼る型。追補ルール6（AIDLC 簡易版ワークフロー）と対で使うと、
「依頼 → 承認」の2アクションで用件確認〜実行〜検証まで流れる。テンプレートなしの普通の
依頼でも動くが、貼ると確認の往復が減る。

```text
## ゴール（1行）
〇〇

## 背景（1行。誰のため・何を可能にするか。上位モデルほど「なぜ」があると精度が上がる）
〇〇

## 完了条件（機械的に判定できる形で）
- 〇〇（例: このテストが通る / このコマンドが exit 0 / この見出しが本文にある）

## スコープ
- 対象: 〇〇 / 非対象: 〇〇

## 制約
- 〇〇（依存追加の可否・既存パターンへの追従など）

## 検証方法
- 〇〇

## 報告形式
- 完了時は検証の証拠（実行コマンド・戻り値・テスト結果）つき。不確かな箇所は確信度 高/中/低 を明記

## 進め方
1. 上記に成果物が変わる曖昧さがあれば、選択肢＋推奨値つきの構造化質問でまず確認する
2. 実行計画には、使うスキル/エージェントの分担と検証チェックポイントを明記して承認を待つ
3. 承認後は独立した作業単位に分割し、確認を挟まず完走する
4. 完了報告の前に、経緯を知らない検証役による敵対的検証を実施し、証拠つきで報告する
```

数時間規模の長時間ループは、本体の `/goal`（完了条件を毎ターン判定）か公式プラグイン **ralph-loop**
（Stop フックで完了まで同じプロンプトを再投入する）を使う。

## 11. テストの棚卸し（削除・統合候補のリストアップ）

増え続けたテストを、件数やカバレッジではなく「保証の価値」で見直す。**洗い出しまでを依頼し、
削除はリストを読んでから別の依頼で行う**（一括削除を許すと、残すべきテストまで消える）。

出典: [catnose99 の X ポスト](https://x.com/catnose99/status/2098238001403113924)（2026-09-11 投稿・2026-10-03 取得）の翻案。

```text
コードベース内の全テストを精査し、削除・統合できるテストをリストアップしてください。
まだ削除・編集はしないこと。
- 候補にする対象: 実装のコピー、モックの自己検証、型やライブラリが既に保証していることの再確認、
  他テストとの重複、内部実装への過度な依存、過剰なケース分け
- 判断基準は「削除すると、どんな現実的な不具合を見逃すか」。候補ごとにそれを1行で書くこと。
  答えが「無い」ものだけを削除候補、他テストで代替できるものは統合候補（統合先を明記）にする。
- 「念のため」を理由に残さない。実行時間・不安定さ・修正負担と、保証の価値を比べること。
- テスト件数やカバレッジの維持そのものを目的にしないこと。
- 出力は ファイル:テスト名 / 区分（削除・統合）/ 見逃す現実的な不具合 / 根拠 の表にする。
```

## 12. AI レビューが収束しないとき（指摘をテストに固定する）

レビュー → 修正 → 再レビューを繰り返しても中程度の指摘が 0 にならないときに使う。原因は
「最初からあった問題の小出しの発見」「修正による新しい問題」「観点の揺らぎによる判定の変化」が
重なることにある。**AI の揺らぐ判定を、テストという再現できる基準に置き換え、終了判断を
「指摘0件」に任せない。** 全件を一度に出させる部分は公式 Opus 5 ガイドの網羅レビューと同じで、こちらは
その後の扱いを決める。#11（テストの棚卸し）とは向きが逆で、こちらはテストを足す側。
出典: [npaka「AIデバッグはなぜ収束しないのか」](https://note.com/npaka/n/n557fb948c3cf)（2026-09-27 公開・2026-10-06 取得）の翻案。

```text
今回は修正しないでください。まずレビューだけを行ってください。
- 重大度の高いものから中程度のものまで、数件見つけても探索を打ち切らず、対象範囲全体の
  レビューが終わるまで続けて全件を列挙すること（呼び出し元とテストも確認する）。
- 指摘ごとに「実際に起きることを確かめる方法」を1行で書くこと（再現する入力・手順）。
修正は、このリストを私が確認してから別の依頼で行います。修正するときは:
- 確かめて実在した問題だけを直し、直した問題ごとに、それを再現するテストを先に追加すること。
- 確かめても再現しなかった指摘は直さず、「再現せず」と理由を残すこと。
- 前回と同じ指摘がまた出たら、コードを変えずに「なぜ繰り返し指摘されるのか」の原因分析だけを返すこと。
終了条件は「指摘が0件と表示されたこと」ではなく、次をすべて満たしたときとする:
重大な指摘が0件 / 確かめた指摘は修正済みで再現テストつき / テスト・型チェック・Lint・ビルドが成功。
```
