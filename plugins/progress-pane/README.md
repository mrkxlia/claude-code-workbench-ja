# progress-pane — Claude Code の中の進捗ダッシュボードとエージェントの地図

Claude Code の **function hooks（mod）** で書いたプラグインです。長時間タスクの「いまどこまで進んだか」
「どのエージェントが何をしているか」「詰まっていないか」を、Claude Code の中の**ペイン1枚**に出します。
**単独で動きます**（他のプラグインも外部ツールも要りません）。**LLM を使わず**、Claude が使うツールの
入出力と本体のエージェント一覧を数えるだけなので、トークンは0です。

`1` `2` `3` のタブで切り替えます（ペインにフォーカスがあるときはキー1つで）。

## 前提（入れる前に確認）

- **タスクの表示には `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` が要ります（現行モデルでは）。** 本体のタスクツール（TaskCreate・TodoWrite など）は
  Claude 3.x・Opus 4〜4.7・Sonnet 4〜4.6・Haiku 4.5 でだけ既定で有効で、Opus 4.8・Sonnet 5・Fable 5 以降では無効です
  （[tools-reference](https://code.claude.com/docs/en/tools-reference)・changelog、2026-10-08 取得）。無効のままだと、進捗バーと
  「15分完了なし」は働かず、エージェントの地図・ツール実行グラフ・連続失敗の検知だけが動きます
- **mods（function hooks）に対応した Claude Code が要ります。** 2.1.294 で確認。API は版によって変わることがあると型定義に書かれています。
  動くのはローカルの端末とデスクトップです（モバイルは表示のみ）

## 何を見ているか

| 表示 | 拾い方 |
|---|---|
| タスクの進捗バー・実行中のタスクと経過時間・一覧 | `TaskCreate`・`TaskUpdate`・`TodoWrite` の入出力 |
| エージェントの地図（親子・状態・経過時間・ツール回数・失敗数・いま使っているツール） | 本体のエージェント一覧（`$.agent.list()`：id・種類・説明・状態・親）を2秒ごとに取り込み、各ツール呼び出しの `agentId` でどのループのものかを数える。一覧から消えたエージェントは最後の状態で残す |
| ツール実行のグラフ（1分ごと・直近30分） | すべてのツール呼び出しの成否。端末は `Raster`（ブロック文字の柱）、デスクトップ・モバイルは `Svg`、VS Code は1行の文字グラフ |
| 経過時間・文脈の使用率・費用 | 本体のセッション使用量（`$.session.usage()`） |
| 同期の健康状態 | エージェント一覧や使用量が取れなくなったら（本体の更新で API が変わったなど）、黙らずにペインとステータスラインに「同期できていません」と出す |
| 詰まり | ①**どれかのループ**でツールが3回続けてエラー（エージェントの名前つきで出す） ②メインのターンが動いていて未完了タスクがあるのに、15分どのタスクも完了しない。人の番で待っている間・質問中・ツールが実行中（長いビルドなど）の間は数えない。初回だけトーストでも知らせ、詰まりが解けるまで鳴らし直さない |
| あなたの回答待ち | `AskUserQuestion` が開いている間 |
| よく使ったツール・直近の失敗（ログのタブ） | 同上。失敗はどのエージェントで起きたかつき |

ステータスラインにも要約（`進捗 3/5 · ▶ … · エージェント 2 実行中 · ⚠ 連続失敗 3`）を出します。

## やらないこと（意図的に）

- **判断待ちを既定の動作で進めない。** 着想元のプロンプト（下記）は「判断が要るときは質問リストに積んで
  既定の動作で進める」としていたが、model-setup のルール2（複数解釈を勝手に選ばない）と矛盾する。
  この mod は見せる・知らせるだけで、続行・方針変更・中断は人間が決める
- **作業を止めない。** 失敗を検知してもツール呼び出しを拒否しない。フックが自分で壊れたときも
  `.catch` で素通りさせる（fail-open）
- **エージェントを操作しない。** 地図は見るだけ（止める・メッセージを送るのは本体の操作で）
- **何も保存しない・どこにも送らない。** 状態はセッションの間だけ本体が持つ（`$.state`）。モデルも呼ばない

## 使い方

- ペインは最初のタスクが作られたときに**セッションで1回だけ自動で開きます**（頼まれずに開くペインは、端末が 144 桁未満だと
  幅が空くまで待ちます）。閉じたら、以後は `/progress` で開いたときだけ出ます
- ペインの本体の幅が 90 桁未満のときは、上の3枚のカードを縦に積みます
- `/clear` や resume で会話が替わったら、前の会話の表示は捨てます

## どれを使うか（先行事例との違い）

2026-10-08 の調査（`/deep-research`）で、部品ごとには先例があることが分かっています。**入れる前に下を見てください。**

| やりたいこと | 先に検討するもの |
|---|---|
| サブエージェントの親子と状態・経過時間・トークンを見る | **本体のサブエージェントパネル**（プロンプトの下。入れ子の木・`(+N)`・状態・トークン。何も入れなくてよい）。`/tasks` も |
| サブエージェントの木と「いま使っているツール」を Claude Code 内で見る | mod の [Charlie0113-T/claude-agent-flow](https://github.com/Charlie0113-T/claude-agent-flow)（`/flow`。2分黙ったエージェントの印つき） |
| ステータスラインにツール・エージェント・タスク数を出す | [jarrodwatts/claude-hud](https://github.com/jarrodwatts/claude-hud) |
| 詰まり（同じエラーの繰り返し・修正したはずの失敗）を手厚く見て、抜け出す操作まで欲しい | mod の [sniperunder123/unstuck](https://github.com/sniperunder123/unstuck)（点数化・赤い帯・元に戻す等の脱出操作） |
| 履歴を残して、ブラウザで細かく分析したい | [hoangsonww/Claude-Code-Agent-Monitor](https://github.com/hoangsonww/Claude-Code-Agent-Monitor)（Node＋SQLite。会話も保存する） |
| task-pipeline のフェーズと承認待ちを見る | [`tools/progress/`](../../tools/progress/) |
| **上を1枚にまとめ、ループごとの連続失敗と「ターン中15分完了なし」を人に知らせ、何も保存しない** | **progress-pane（本プラグイン）** |

progress-pane に残る差分は、タスクの進捗バー・1分ごとのツール実行グラフ・ループごとの連続失敗の検知・「ターン中15分完了なし」を
1枚のペインにまとめ、依存・保存・モデル呼び出しなしで動くことです。エージェントの地図そのものは新しくありません。

## ファイル構成

```
progress-pane/
├── README.md                     # このファイル
├── .claude-plugin/plugin.json    # マニフェスト（types で $.state の型契約を宣言）
├── hooks/
│   ├── hooks.json                # { "modules": ["./register.tsx"] }
│   ├── register.tsx              # フック（tool.call・prompt.submit・command.run）と描画（ui.render の Pane）
│   └── model.ts                  # 状態の更新と表示用の計算（木・グラフのセル・SVG）。エンジンに触れない純粋な関数
├── types/index.d.ts              # $.state（progress-pane.watch・progress-pane.tab）の型契約
└── tests/progress-pane.test.ts   # claude plugin test で走る18件
```

## 導入方法

```
/plugin marketplace add mrkxlia/claude-code-workbench-ja
/plugin install progress-pane@workbench-ja
```

開発中のフォルダをそのまま試すなら `claude --plugin-dir <このフォルダ>` で起動します。
閾値（3回・15分）は `hooks/model.ts` 冒頭の `STREAK_LIMIT`・`IDLE_LIMIT_MS` で変えられます。

**動く条件。** 上の「前提」を参照。フックが壊れても作業は止めません（fail-open）。一覧や使用量が取れなくなったときは
「同期できていません」と出しますが、ツール呼び出しの観測そのものが止まった場合は表示が更新されなくなるだけです。

## 検証

```
claude plugin validate plugins/progress-pane
claude plugin test plugins/progress-pane
```

テストは18件です。状態の計算（木・グラフのセル・タスクの差し替え・詰まりの判定）を関数単位で、描画と通知をエンジン経由で確かめます。
敵対的レビューで見つかった欠陥（並列呼び出しでトーストが何度も鳴る・内部のフォークが「実行中」のまま残る・ドックした狭いペインで
はみ出す・新しいタスクを足した瞬間に詰まり扱い・中断で回答待ちが残る・バックグラウンドの通知で数え直す・人の番の時間を数える・
閉じても開き直す・`/clear` 後に前の表示が残る・同期が止まっても黙る）は、それぞれ再発防止のテストがあります。

**実機（端末・デスクトップの画面）での描画は、まだ確かめていません。** テストはテストキット上の描画と状態遷移です。
