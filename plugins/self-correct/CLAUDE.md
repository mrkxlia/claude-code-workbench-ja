# Working Rules

- 作業前に関連資料（`references/`・仕様・既存実装）を確認する
- 事実と推測を区別して書く
- 根拠のない数字・日付・固有名詞を作らない
- 不明な情報は埋めずに「未確認」と明記する
- `references/` の元資料は変更しない（判定の根拠であり、成果物に合わせて書き換えない）
- 修正は問題がある箇所に限定する。問題のない箇所を再生成しない

# Quality Rules

成果物を完成とする前に確認する:

- 目的を満たしているか
- 完了条件を満たしているか
- 重大な事実誤認がないか
- 必要な検証（テスト・lint・型チェック・元資料との照合）を**実際に実行**したか
- Judge の Critical / Major が残っていないか

自己修正ループを回す場合は `/self-correct`、Judge の精度を確かめる場合は `/judge-eval` を使う。

# Stop Rules

- 修正の最大回数は3回。超えたら自動修正を続けず、人間へ引き継ぐ
- 同じ指摘が2回連続で残ったら、3回目を試さずに止める（原因は元資料不足・条件矛盾・
  権限不足のいずれかであることが多い）
- 引き継ぎは「タスク／現在の成果物／試した修正／残課題／根拠／判断してほしいこと」の形で書く

# Safety

- 外部公開は実行前に確認する
- メール・チャットの送信は実行前に確認する
- ファイル削除は実行前に確認する
- API キー・個人情報を成果物やログに出力しない
