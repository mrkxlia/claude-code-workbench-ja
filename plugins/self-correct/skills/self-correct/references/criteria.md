# 評価基準と完了条件の書き方

自己修正ループが終わらない原因のほとんどは、モデルの能力ではなく**基準が測れないこと**にある。

## 原則: 「何をしてほしいか」ではなく「どんな状態なら終わりか」

- 悪い: 「最高の記事にする」「品質を上げる」「読みやすくする」
  → 「最高」を判定できないので、Judge は何度でも改善余地を見つけられる。ループが止まらない
- 良い: 「`references/` に無い数字・日付・固有名詞を断定していない」「各章に具体例が1つ以上ある」
  「20,000字以内」「同じ主張を3回以上繰り返していない」
  → どれも成果物を見れば YES / NO を答えられる

## 基準の書き方（5つのチェック）

1. **独立して判定できるか。** 1基準1論点。「正確で読みやすい」は2つに割る
2. **YES / NO で答えられるか。** 程度を問う基準（「十分に詳しい」）は閾値に変える
3. **判定の根拠があるか。** 何と突き合わせるかが言えるか（[`ground-truth.md`](ground-truth.md)）
4. **場所を特定できるか。** FAIL したとき、直す箇所が一意に決まるか
5. **数が多すぎないか。** 基準が20個を超えたら、Critical になりうるものだけに絞る

## 重大度の定義（プロジェクトで上書き可）

| 重大度 | 定義 | ループでの扱い |
|--------|------|---------------|
| Critical | 重大な事実誤認、安全上の問題、必須要件の欠落、テスト・ビルドの失敗 | 0件になるまで RETRY |
| Major | 目的を損なう構成・論理・仕様上の問題 | 0件になるまで RETRY |
| Minor | 表現・読みやすさ・軽微な改善 | 修正しない。全件を報告に載せて人間の判断に委ねる |
| UNVERIFIED | 根拠に到達できず判定できなかった | 重要な基準なら追加調査、取れなければ ESCALATE |

**Minor を修正対象にしない。** Minor で RETRY を消費すると、上限に達したときに残るのが
Critical という最悪の配分になる。

## 記述テンプレート

```
目的: <1文>
成果物: <パス>
Ground Truth: <元資料のパス / 公式 URL / 実行するコマンド>
変更禁止: <パス>

評価基準
  1. [Critical] 数字・日付・固有名詞が references/ の記載と一致している
  2. [Critical] references/ に無い事実を断定していない（未確認は「未確認」と明記）
  3. [Major]    各章に具体例が1つ以上ある
  4. [Major]    同じ主張を3回以上繰り返していない
  5. [Minor]    専門用語に初出時の説明がある

完了条件: Critical = 0 / Major = 0 / 重要な UNVERIFIED = 0
停止条件: 修正3回で未達なら停止し、残課題を報告する
```

## /goal に書くときのテンプレート

`/goal` の条件は**最大4,000字**。詰め込みすぎると評価器が判定できなくなるので、
基準そのものではなく**ループの完了状態**を書く。

```
/goal <成果物> について loop-builder と loop-judge を使って改善する。次をすべて満たしたら完了:
- Judge の Critical が0件
- Judge の Major が0件
- 重要な UNVERIFIED が0件
- <変更禁止パス> を変更していない
- 問題がない箇所を不必要に書き換えていない
- 最大<N>ターンで未達なら停止し、残課題を報告する
```

コードなら、評価器が会話の報告から判定できる形にする:

```
/goal 次の状態にする。
- auth 関連の全テストが PASS（実行結果を会話に出す）
- lint エラー0件・型エラー0件
- auth 以外の既存機能を変更しない
- 新しい依存関係を追加しない
- 最大10ターンで未達なら停止し、残っているエラーを報告する
```

## よくある壊し方

| やってしまうこと | 何が起きるか | 代わりに |
|---|---|---|
| 「必ず3件は問題を見つけて」と Judge に指示する | 問題が0件でも3件捏造する | 「0件なら0件でよい。基準ごとに独立に判定する」 |
| 基準に「良い」「適切な」を使う | 判定が主観になり、ループが終わらない | 閾値・照合先・有無に置き換える |
| 基準を後から増やしながら回す | 前ラウンドの PASS が無効になり、収束しない | 基準は Phase 0 で凍結する。追加が要るなら一度止めて合意する |
| Minor まで RETRY 対象にする | 上限を消費し、Critical が残る | Minor は報告のみ |
| UNVERIFIED を PASS 扱いにする | 未確認情報が「確認済み」として出荷される | 追加調査、または ESCALATE |
