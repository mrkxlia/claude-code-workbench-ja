# adoption-review — 採用可否の敵対的レビュー

流れてきた技術（OSS・AI ツール・SaaS・開発手法・論文・スライド・X ポスト・記事）について、
**「これは本当に実務で採用する価値があるのか」**だけを判定する Claude Code スキル＆
エージェント一式です。

`/adoption-review https://github.com/owner/repo` のように対象を渡すと、Web で一次情報を
集め、**良い点より先に「採用しない理由」を探し**、代替手段とコストまで見てから、
結論・採用判断・検証手順・スコアを返します。

## なぜ必要か

新しいツールの評価は、放っておくと次のように壊れます。

- **話題性が根拠にすり替わる** — スター数・フォロワー数・「話題の」という枕詞・紹介者への信頼
- **良い点から探し始める** — 最初に長所を並べると、その後の欠点が「とはいえ」に格下げされる
- **「面白い」と「実務で使える」が混ざる** — 面白さは採用理由にならない
- **不明点が推測で埋まる** — 「たぶん保守されている」が、いつのまにか前提になる
- **コストが数えられない** — 導入だけ見て、運用・学習・**撤退**のコストを勘定に入れない

このスキルは、この5つをそれぞれ手順で潰します。**不明は「確認できなかった」と書く**、
**数値は記録するが採用理由にしない**、**必ず代替手段（何もしないを含む）と比べる**、
**良く見えたときだけ敵対役を追加で当てる**、が中核です。

## 収録物

### スキル1種

| スキル | 呼び出し | 何をするか |
|---|---|---|
| **adoption-review** | `/adoption-review [対象]` ／自然文（「これ実務で使える？」「辛口で評価して」） | 種別判定 → 証拠収集（並列）→ 主張の分解 → 敵対的批判 → 代替手段 → コスト → 出力 |

### サブエージェント2種

| エージェント | tools | 役割 |
|---|---|---|
| **adoption-researcher** | Read, Grep, Glob, WebSearch, WebFetch | 割り当てられた1スコープだけを調べ、**事実と出典 URL だけ**を返す（評価しない）。1ソース1体で並列起動 |
| **adoption-challenger** | Read, Grep, Glob, WebFetch | 証拠だけを受け取り「**採用しない論拠**」だけを構築する敵対役。**結論が肯定寄りのときだけ**起動する |

フックはありません（導入しても勝手には発火しません）。

## 導入

### 方法1: プラグインで導入する

```
/plugin marketplace add mrkxlia/claude-code-workbench-ja
/plugin install adoption-review@workbench-ja
```

### 方法2: コピーして導入する

```bash
mkdir -p .claude/skills .claude/agents
cp -r plugins/adoption-review/skills/*  .claude/skills/
cp -r plugins/adoption-review/agents/*  .claude/agents/
```

グローバルに使いたい場合は `~/.claude/skills/`・`~/.claude/agents/` にコピーします。

## 使い方

```
/adoption-review https://github.com/owner/repo
/adoption-review この論文の手法、うちで使える？ https://arxiv.org/abs/xxxx.xxxxx
/adoption-review （X ポストの本文を貼り付け）
```

自然文でも発動します（「これ実務で使える？」「このツール採用する価値ある？」「バズってる
けど本当に使えるの？」「導入すべき？」）。

出力は固定の型です — **結論**（採用候補／条件付きで有用／試す価値はあるが常用は微妙／
面白いが実務採用は弱い／現時点では不要／ほぼ無視でよい／危険なので避けるべき）→ 何が
主張されているか → 本当に良い点 → 怪しい点・過大評価ポイント → 反証・代替仮説 →
**採用判断**（今すぐ導入する／小さく検証する／特定用途だけ使う／情報収集に留める／
採用しない／避ける）→ 試すなら検証方法 → 8観点のスコア → 一言総括 →
**確認できなかったこと**。

## 他プラグイン・本体機能との住み分け

| やりたいこと | 使うもの |
|---|---|
| **外部の技術**を採用すべきか判断したい | **本プラグイン** |
| 自分のコード差分・実装計画・ドキュメントを多視点で討論させたい | [`agent-review-panel`](../agent-review-panel/) の `/review-panel` |
| コードの行レベルのレビューが欲しい | 本体の `/code-review`・[`codex-bridge`](../codex-bridge/)・[`kiro-bridge`](../kiro-bridge/) |
| 別の AI の意見が聞きたい | `/codex-ask`・`/kiro-ask`、または内蔵の Task サブエージェント |
| 成果物が完了条件を満たすか判定したい | [`model-setup`](../model-setup/) の `/verify-fresh` |

## 限界（過信しないこと）

- **Web で取れない対象がある** — X はログイン必須で取得できないことが多く、PDF が画像のみの
  こともある。そのときスキルは推測で埋めず「確認できなかった」と書きます。**判断材料が薄い
  という事実**は残りますが、それ以上のことは分かりません
- **スコアは絶対値ではない** — 8観点の点数は、同じセッションの中で相対的な重みを示すための
  ものです。他のレビューのスコアと直接比べないでください
- **同一モデルのバイアスは消えない** — challenger も同じ Claude です。構造（結論を渡さない・
  肯定寄りのときだけ当てる）で偏りを減らしますが、モデル自体が共有する偏りは残ります
- **最終判断は人間** — 出力はあくまで「採用しない理由が十分に探された状態の材料」です
