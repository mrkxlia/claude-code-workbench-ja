# codex-ask — Codex に相談する／セカンドオピニオン（/codex-ask）

設計の是非・代替案・デバッグ方針・トレードオフなど、**自由形式の相談**を
**OpenAI Codex** に投げて意見をもらうスキルです。ユーザーは Codex を直接操作しません。
Claude Code が Codex CLI を**非対話モード**（`--sandbox read-only`）で駆動し、Codex の
回答を要約して提示します。実際の codex 実行は **`codex-advisor` サブエージェント**に
委譲し、冗長な出力をメインの文脈から隔離します。

## 使い方

- `/codex-ask この設計（〜）は妥当？代替案は？`
- `/codex-ask なぜこのテストが落ちるか方針を相談したい @path/to/test`

「Codex に相談して」「codex の意見も聞いて」のような自然文でも発動します。

## 他スキルとの違い

- **codex-review** … 差分/コードの**指摘**（重大度 P1–P4）。「悪いところを挙げて」。
- **codex-ask** … 自由形式の**助言・議論**。「どう設計すべき？」「この方針は妥当？」。
- **codex-implement** … コードを**書かせる**。codex-ask は read-only で書き換えない。
- **相談相手を変えたいとき**: 依存を増やしたくない・オフライン/git なし環境なら、内蔵の Task
  サブエージェント（fresh context）に相談内容を渡して第二の視点を得る。codex-ask は相談相手が
  **Codex**（`codex` CLI）である点が違う。

## 前提

`codex` CLI が導入・認証済みであること（`codex-bridge/README.md` の「前提」参照）。
未導入・未認証の場合、サブエージェントが日本語で案内して終了します。

## Common Issues

| 症状 | 原因 | 対処 |
|---|---|---|
| 「codex CLI が見つかりません」で終わる | `codex` が未導入、または PATH に無い | `codex-bridge/README.md` の「前提」を案内する。導入待ちにせず、内蔵の Task サブエージェントで代替してよいか聞く |
| 認証エラーで終わる | Codex が未認証・トークン失効 | 再認証を案内する。ここで実行を強行しない |
| 回答が一般論に終始する | 質問に文脈（対象ファイル・制約・前提）を同梱していない | 関連ファイルの内容と制約を明示して1回だけ再依頼する。それでも一般論なら、そのまま提示して判断をユーザーに委ねる |
| 応答が途中で切れる | 同梱した文脈が大きすぎる | 「全文 → 関連抜粋 → 要約」の順に降格して再依頼する |
| Codex が実装を始めてしまった | read-only のはずが書き込みモードで起動した | **即座に停止して報告する。** 変更が入っていれば `git status` で差分を示し、意図しない変更は戻す |
| ユーザーが実装まで求めている | 相談ではなく実装の依頼だった | `/codex-implement` に引き継ぐ（このスキルは助言のみ） |

## フロー

1. **相談内容を整理する** — 何を判断したいか、選択肢、制約を明確にする。
2. **明らかに関係するファイル内容を用意する** — 相談に必要な抜粋を渡し切る
   （大きすぎる場合は関連箇所に絞る）。
3. **`codex-advisor` を起動する**（Task ツール） — 相談内容と同梱ファイルを渡す。
   サブエージェントが Codex を read-only で実行し、回答要約を返す。
4. **結果を提示する** — 結論・根拠・推奨アクション・留意点を見せる。
5. **必要なら橋渡しする** — 方針が固まったら `/codex-implement`（実装）や
   `/codex-review`（レビュー）に続けることを提案する。

### 実装計画（プラン）のレビューに使う場合

プランモードのプランをユーザーに提示する前に Codex の目を通すときは、上のフローを次のように読む
（`plan-review-codex.sh` フックを配線している場合、Claude はここへ誘導される）。

- **プラン全文＋判断に必要なファイルの内容**を heredoc で同梱する。パスの名指しだけにしない。
- プランを更新して再レビューするときも、**毎回プラン全文を渡し直す**。
  `codex exec resume --last` は使わない — `--last` は「同じ作業ディレクトリの最後のセッション」
  であり、`/codex-review`・`/codex-implement` と混在すると無関係なセッションに継ぎ足しうる。
- 指摘は**抑制させず全部出させて、提示側で落とす**（「致命的な点だけ挙げろ」と指示しない。
  見落としが増える方向のため）。ユーザーに見せるのは P1・P2 だけにし、P3 以下は件数を添える。
- **プランを直すのは Claude**。Codex には実装させない（read-only のまま）。

## このスキルがやらないこと

- ユーザーに codex を手動で叩かせる（すべて Claude が非対話で駆動する）
- リポジトリのファイルを編集する（read-only。書かせたいなら `/codex-implement`）
