# codex-ask — Codex に read-only で相談する（/codex-ask）

設計の是非・代替案・デバッグ方針・トレードオフなど、**自由形式の相談**を **OpenAI Codex** に投げて
意見をもらう入口です。Codex の起動・実行は **OpenAI 公式の [codex-plugin-cc](https://github.com/openai/codex-plugin-cc)**
（`codex:codex-rescue` サブエージェント）に任せ、このスキルは**相談として渡す作法**だけを持ちます。

公式の `codex:codex-rescue` は、相談だと明示しないと**書き込みモード（`--write`）で起動する**のが既定です。
このスキルの役目は、毎回「read-only・編集禁止の相談」として渡し、返ってきた回答を要約することです。

## 前提

公式プラグインが導入・セットアップ済みであること:

```
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/codex:setup
```

`codex:codex-rescue` が使えない（未導入・未認証）ときは、上の手順を案内して止まる。自分で `codex` CLI を
叩いて代わりに実行しない。

## フロー

1. **相談内容を整理する** — 何を判断したいか、選択肢、制約を明確にする。
2. **明らかに関係するファイル内容を用意する** — 相談に必要な抜粋をプロンプトに入れる（パスの名指しだけにしない。
   大きすぎる場合は関連箇所に絞る）。
3. **`Agent` ツールで `codex:codex-rescue` を起動する**（`subagent_type: "codex:codex-rescue"`、前景で実行）。
   プロンプトの先頭に必ず次を入れる:
   - 「`--fresh` で新しいスレッドとして実行する。`--write` を付けない（read-only）」
   - 「これは相談であり、ファイルを編集しない。結論・根拠・代替案・留意点を答える」

   `Skill(codex:rescue)` は呼ばない（公式の注意書きどおり、同じコマンドに再入してセッションが止まる）。
4. **結果を提示する** — Codex の回答の要点（結論・根拠・推奨アクション・留意点）を日本語で要約し、
   必要なら原文の該当箇所を引く。
5. **必要なら橋渡しする** — 方針が固まったら、実装は `/codex:rescue`（書き込み可）、差分のレビューは
   `/codex:review`・`/codex:adversarial-review` を案内する。

### 実装計画（プラン）のレビューに使う場合

プランモードのプランをユーザーに提示する前に Codex の目を通すときは、上のフローを次のように読む
（`plan-review-codex.sh` フックを配線している場合、Claude はここへ誘導される）。

- **プラン全文＋判断に必要なファイルの内容**をプロンプトに入れる。
- プランを更新して再レビューするときも、**毎回 `--fresh` でプラン全文を渡し直す**（前のスレッドを継がない —
  他の作業で張られた Codex スレッドの文脈に継ぎ足さないため）。
- 指摘は**抑制させず全部出させて、提示側で落とす**（「致命的な点だけ挙げろ」と指示しない）。ユーザーに見せるのは
  P1・P2 だけにし、P3 以下は件数を添える。
- **プランを直すのは Claude**。Codex には実装させない（read-only のまま）。

## Common Issues

| 症状 | 原因 | 対処 |
|---|---|---|
| `codex:codex-rescue` が見つからない | 公式プラグインが未導入 | 「前提」の導入手順を案内する。導入待ちにせず、内蔵の Agent サブエージェントで代替してよいか聞く |
| 「`/codex:setup` を実行して」と返る | Codex が未導入・未認証 | `/codex:setup` を案内する。ここで実行を強行しない |
| Codex がファイルを書き換えた | 渡すときに read-only の指示が抜けた | **即座に止めて報告する。** `git status` で差分を示し、意図しない変更は戻す。次からフロー3の2行を必ず入れる |
| 回答が一般論に終始する | 文脈（対象ファイル・制約・前提）を入れていない | 関連ファイルの内容と制約を入れて1回だけ再依頼する |
| ユーザーが実装まで求めている | 相談ではなく実装の依頼 | `/codex:rescue` を案内する（このスキルは助言のみ） |

## このスキルがやらないこと

- `codex` CLI を自分で叩く（実行は公式プラグインに任せる）
- リポジトリのファイルを編集する・Codex に編集させる
- 名指しの無い「セカンドオピニオン」を横取りする（内蔵の Agent サブエージェントに任せる）
