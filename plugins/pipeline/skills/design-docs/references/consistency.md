# フェーズ間の整合をどう保つか

設計書が破綻する典型は、書き方の巧拙ではなく**フェーズをまたいだときのズレ**である。
このリポジトリでは以下の4つを仕組みで防ぐ。

| つまずき | 原因 | 対策 |
|---|---|---|
| フェーズ間で内容が矛盾する | 前段の設計書を見ずに書いている | 前段の**ファイルパス**を入力に必ず含める（記憶で引き継がない） |
| 用語の表記がフェーズごとに違う | 用語集が共有されていない | 用語集を導入先 CLAUDE.md に1か所だけ置き、全フェーズがそこを参照する |
| 詳細設計が実装と食い違う | コードを読まずに想像で書いている | 詳細設計・DB設計では Grep/Glob で実コード・マイグレーションを読んでから書く |
| 図が複雑になりすぎる | 1つの図に全処理を入れている | 機能単位・シナリオ単位で図を分ける（ノード15個が目安） |

## 用語集の置き方

導入先リポジトリの `CLAUDE.md` に「用語集」節を作り、**設計書側には複写しない**。

```markdown
## 用語集

| 用語 | 意味 | 使わない言い換え |
|---|---|---|
| ユーザー | 本サービスにログインして操作する人 | 会員・アカウント・顧客 |
| テナント | 契約単位の組織 | 企業・会社・組織 |
| 通知 | システムがユーザーに送る非同期メッセージ | お知らせ・アラート |
```

- 「使わない言い換え」列が要点。**禁止語を書いておくと機械的に検査できる**
  （`design-doc-checker` はこの列を grep 対象にする）
- 用語が増えたら CLAUDE.md 側だけを直す。設計書は次回更新時に追随させる

## 前段の引き継ぎで渡すもの

次フェーズのエージェント／セッションには、以下を**パスとして**渡す。本文の貼り付けで済ませない
（長文の貼り付けはコンテキストを食い、途中で切れても気づけない）。

1. 前段設計書のパス（複数フェーズあるときは全部）
2. 用語集の場所（`CLAUDE.md` の「用語集」節）
3. 実コードの入口（詳細設計・DB設計のみ。対象モジュールのディレクトリ、マイグレーションの場所）
4. 前段に残っている `【要確認】` の一覧（未解決のまま次に進んでよいかの判断材料）

## コード乖離の見つけ方

詳細設計・DB設計の検査では、設計書の記述を**そのまま検索語にして実在を確かめる**:

- クラス名・メソッド名 → `Grep` で定義の実在を確認（無ければ乖離）
- ファイルパス → `Glob` で存在確認（`ファイル:行` が古いままの指摘が最も多い）
- テーブル名・カラム名 → マイグレーション／スキーマ定義に対して確認
- エンドポイント → ルーティング定義に対して確認

**設計書が先・実装が後**の段階では、乖離ではなく「未実装」である。
どちらなのかは設計書のヘッダブロック（版・前段文書）と実装状況から判断し、
判断がつかないものは Critical にせず Important として「どちらか確認が要る」と報告する。

## design-doc-checker への入力

Task ツールで `design-doc-checker` を起動するときは、次の4点を渡す:

```
- 検査対象: docs/design/detailed-design-notification.md
- 前段設計書: docs/design/basic-design-notification.md, docs/design/requirements.md
- 用語集: CLAUDE.md の「用語集」節
- 実コードの入口: src/server/notifications/, prisma/migrations/
```

checker は read-only で、**指摘するだけで直さない**。修正は書き手（単発モードなら本人、
連結モードなら `deliverable-builder`）に差し戻す。

## final-reviewer との使い分け

| 観点 | final-reviewer | design-doc-checker |
|---|---|---|
| 突き合わせ先 | 承認済みの要件・ブリーフ | 前段設計書・用語集・実コード |
| 主な検出物 | 未カバーの受け入れ基準、スコープ外の変更、根拠のない記述 | フェーズ間矛盾、用語ゆれ、コード乖離、未回収の【要確認】、テンプレ逸脱 |
| いつ | task-pipeline の Phase 5 | 設計書を1本書き終えるたび／Phase 5 で併走 |

両者は検査対象が違う。**どちらか一方で代替しない。**
