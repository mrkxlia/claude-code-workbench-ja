# SPEC 要約の抽出規則（`inject-spec-summary` の単一定義）

`inject-spec-summary.sh` と `inject-spec-summary.ps1` は同じ抽出をしなければならない。
**両方が写す元の定義はこのファイル1か所**とする（片方だけ更新される事故を防ぐため。
スクリプトを変更したらここも直す）。

## 対象ファイル

リポジトリ直下を次の順で探し、最初に見つかった1つだけを使う（`spec-sync-reminder` と同じ順序）:

1. `SPEC.md`
2. `SPEC-recovered.md`

どちらも無ければ「SPEC.md なし」の1行だけを返す。

## 抽出する行

**要件 ID と確度ラベル `[確定]` の両方を含む行**を、ファイルに現れる順で拾う。

| 項目 | 値 |
|---|---|
| 要件 ID | `[FD]-[0-9][0-9]*`（コードモードは `F-NN`、成果物モードは `D-NN`） |
| 確度ラベル | `[確定]`（`[推定]`・`[不明]`・`[廃止]` は拾わない） |
| POSIX ERE | `(^\|[^A-Za-z0-9])[FD]-[0-9]+([^0-9]\|$)` と `\[確定\]` の **両方**にマッチする行 |

`[確定]` 以外を拾わないのは、注入するのが「守るべき確定要件の目次」だからである。
`[推定]`・`[不明]` は researcher / clarify が詰める対象であって、遵守を強制する対象ではない。

## 各行の整形

1. 前後の空白と、表の行頭・行末の `|` を落とす
2. `|`（表のセル区切り）で分割し、**先頭3セットまで**を ` / ` で連結する
   （通常は ID / 要件 / 確度ラベル）。4セル目以降があれば末尾に ` …` を付ける
3. 全体で最大 **60 行**、かつ **6000 バイト**まで。超えた分は**行ごと**落とし、
   「ほか N 件」と件数を書く

**文字数での切り詰めはしない。** 切るのは必ず ASCII の `|` かあるいは行の境界に限る。
UTF-8 の途中で切ると、`SubagentStart` に渡す JSON 文字列が不正なバイト列になるため
（日本語の SPEC.md では ID・数字が混ざった行のバイト位置がちょうど文字境界に来ない）。

上限を置くのは、フック出力が 10,000 字で切られるため（超過分はファイルへ退避されるが、
中途半端に切れた目次より件数を正直に書くほうが読み手に親切）。

## 出力に必ず含める文言

要約は目次であって本文ではない。読んだ気にさせないため、次の1行を必ず添える:

> これは目次であり本文ではありません。判断の前に <パス> の本文を読んでください。

## 出力先の使い分け

| イベント | 形式 |
|---|---|
| `SessionStart` | プレーンテキストを stdout へ（Claude Code がそのまま文脈に入れる仕様。JSON を組み立てない） |
| `SubagentStart` | `{"hookSpecificOutput":{"hookEventName":"SubagentStart","additionalContext":"..."}}` を1行 |

イベントの判別は stdin の JSON の `hook_event_name` で行う。判別できないときは
プレーンテキスト（SessionStart 側）として出力する。
