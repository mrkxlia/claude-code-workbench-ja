# checklist — 手順書の検査項目

## 目次

- 使い方と深刻度
- レベル1 論理的（矛盾・欠陥が無いか）
- レベル2 合目的的（手順どおりで目的を果たせるか）
- レベル3 伝承的（意図が伝わり、引き継げるか）
- 一般（runbook の一般的な実践）
- 報告の書式

## 使い方と深刻度

上から順に当てる。該当した項目だけを、**場所（ファイル・タスク・手順番号）と直し方**つきで報告する。

| 深刻度 | 基準 |
|---|---|
| **Critical** | そのまま実施すると事故（誤った対象への変更・取り消せない損失・目的未達のまま完了扱い）に直結する |
| **Important** | 実施者が迷う・止まる・聞き返す。事故には直結しないが、試走で必ず引っかかる |
| **Minor** | 読みやすさ・表記の揃え |

出典の区分: **[OpsLab]** は運用設計ラボの発表（SKILL.md 冒頭の出典）に由来する項目、
**[一般]** は runbook の一般的な実践、**[補完]** は発表で「論点整理中」とされた部分をこのリポジトリが補った項目。

## レベル1 論理的（矛盾・欠陥が無いか）

| # | 項目 | 深刻度の目安 | 出典 |
|---|---|---|---|
| L1-1 | タスクの中に分岐（「〜の場合は」）がある。分岐はシナリオの分岐表に移す | Important | [OpsLab] |
| L1-2 | 同じ手順が2か所以上に書かれている（共通化されていない）。1タスクにしてシナリオから呼ぶ | Important | [OpsLab] |
| L1-3 | 共通化したタスクの中に、特定のシナリオの事情が書かれている（不適切な共通化） | Important | [OpsLab] |
| L1-4 | タスク N の事前条件と、タスク N-1 の完了条件が一致しない（文言・確認方法が違う） | Critical | [OpsLab] |
| L1-5 | 分岐のどれかが行き止まり（次のタスク・別シナリオ・中止と連絡先のどれにも行かない） | Critical | [一般] |
| L1-6 | 分岐の条件が網羅されていない（A・B 以外の結果が出たときの行き先が無い） | Important | [一般] |
| L1-7 | 1タスクが2種類以上の操作（作成と削除など）を含む | Minor〜Important | [OpsLab] |
| L1-8 | 設定値が手順本文に直書きされている、または同じ値が別の名前で2か所にある | Important | [OpsLab] |
| L1-9 | I/O 一覧で、使われない出力・作られない入力がある | Important | [OpsLab] |

## レベル2 合目的的（手順どおりで目的を果たせるか）

| # | 項目 | 深刻度の目安 | 出典 |
|---|---|---|---|
| L2-1 | シナリオの完了条件が、作業の目的を表していない（「全手順を実施した」になっている） | Critical | [OpsLab] |
| L2-2 | タスクの完了条件に確認方法か期待結果が無い | Critical | [OpsLab] |
| L2-3 | 期待結果が「正常であること」「問題ないこと」のように判定できない | Important | [一般] |
| L2-4 | 事前条件が欠けている（権限・ツール・認証情報・環境変数・先行作業・対象の状態） | Critical | [OpsLab][一般] |
| L2-5 | 前処理（事前条件の確認）が無い、または満たさないときに止まる指示が無い | Critical | [OpsLab] |
| L2-6 | 後処理（完了条件の確認）が無い | Critical | [OpsLab] |
| L2-7 | 事前条件・完了条件が「目的」「前提」として散文で書かれているだけで、確認できる形になっていない | Important | [OpsLab] |
| L2-8 | 中断したとき、どこから再開すればよいかが決まらない（タスクの単位が大きすぎる） | Important | [OpsLab] |
| L2-9 | 時間に制約のある手順に、待ち時間の上限と超えたときの行き先が無い | Important | [一般] |

## レベル3 伝承的（意図が伝わり、引き継げるか）

発表ではレベル3の具体的な基準は「論点整理中」とされている。以下は**読み手を想定した補完**で、
Critical は付けない（事故に直結するものはレベル1・2で拾っている）。

| # | 項目 | 深刻度の目安 | 出典 |
|---|---|---|---|
| L3-1 | タスクの「目的（なぜ）」が無い、または操作の言い換えになっている（「サービスを停止するため」） | Important | [補完] |
| L3-2 | 想定読者が知らない用語・略語・社内の呼び名が説明なしで出てくる | Important | [補完] |
| L3-3 | 書き手の頭の中にしか無い前提がある（「いつもの」「例の」「前回と同じ」） | Important | [補完] |
| L3-4 | なぜこの順序なのか（入れ替えると何が起きるか）が、順序が重要な箇所で書かれていない | Minor〜Important | [補完] |
| L3-5 | タスクの構造（ヘッダ → 設定値 → 前処理・主処理・後処理 → 戻し方）がタスクごとにばらばら | Minor | [OpsLab] |
| L3-6 | 最終更新の日付と理由が無い（いつの環境を前提にしているか分からない） | Minor | [一般] |
| L3-7 | 簡易版と完全版が食い違っている | Important | [OpsLab] |

## 一般（runbook の一般的な実践）

| # | 項目 | 深刻度の目安 | 出典 |
|---|---|---|---|
| G-1 | 状態を変える手順の後に、確認方法と期待結果が無い | Critical | [一般] |
| G-2 | 戻し方が無い、または「戻せない」と書かれていない | Important〜Critical | [一般] |
| G-3 | 取り消せない操作（削除・上書き・外部送信・課金）に警告と直前の確認が無い | Critical | [一般] |
| G-4 | 取り消せない操作が手順の途中に埋もれている（見出し・警告で目立たせていない） | Important | [一般] |
| G-5 | コマンドがコピーしてそのまま実行できない（プレースホルダの書き方が不統一・行の途中で切れている） | Important | [一般] |
| G-6 | 対象が名指しされていない（どのホスト・どのアカウント・どのファイルか） | Critical | [一般] |
| G-7 | 推測語（「たぶん」「通常は」「大抵」「試してみる」「場合による」） | Important | [一般] |
| G-8 | 「問題があれば担当者に連絡」で終わり、何が出たら誰に何を伝えるかが無い | Important | [一般] |
| G-9 | 順序のある手順が番号なしの箇条書き | Minor | [一般] |
| G-10 | 認証情報・秘密の値が手順書に直書きされている | Critical | [一般] |

## 報告の書式

```
## 検査結果: [手順書のパス]
型: [簡易版 | 完全版 | 完全版＋実行ガード]  Critical: N / Important: N / Minor: N / 【要確認】: N

### Critical
- [L2-2] tasks/T03-config-update.md 後処理 — 完了条件「設定が反映されていること」に確認方法が無い
  → 直し方: `[確認コマンド]` の出力に `[期待する行]` が含まれる、と書く

### Important
...

### 3層に分けるとしたら（レビュー時のみ）
- シナリオの分岐: [どこで分かれるか]
- タスク候補: [名前の一覧]
- 重複している手順: [どこ と どこ]
```

Critical が0件になるまで「完成」と言わない。`【要確認】` が残っているものはドラフトとして返す。
