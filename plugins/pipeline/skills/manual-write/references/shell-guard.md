# shell-guard — 構造化した手順書に添える実行ガード（シェル関数の骨格）

**作業がほぼ CLI（bash）で完結し、誤操作の影響が大きいときだけ**使う。GUI・Windows の画面操作が
主体の作業には付けない。

## 何をするための仕組みか

運用設計ラボの発表は、手順書のタスクをシェル関数に対応させている — 実行部が関数、設定値が引数、
前処理・主処理・後処理が関数の本体。そのうえで **全コマンドの前提を確認し、1つでも満たさなければ
主処理を実行させない**、**完了条件の確認が全部通ったらターミナルを閉じてシェル変数の汚染を防ぐ**、
という2つの仕組みで誤操作を起こしにくくしている。

発表に実装は公開されていない。以下は**このリポジトリが上の2つの考え方を再構成した骨格**であり、
発表の実装そのものではない。ターミナルを閉じる代わりに**タスクを新しいプロセスで実行する**
（変数がタスクの外に漏れない、という同じ目的を、作業者の画面を閉じずに達成する）。

## 骨格（1タスク＝1ファイル）

```bash
#!/usr/bin/env bash
# T01 バックアップ取得（作成）
# 使い方: bash tasks/T01-backup-create.sh   ← 必ず新しいプロセスで実行する（source しない）
set -u -o pipefail

# ---- 設定値（シナリオの設定値ファイルから読む。ここに値を直書きしない）----
SCENARIO_ENV="${SCENARIO_ENV:?シナリオの設定値ファイルのパスを SCENARIO_ENV に入れる}"
# shellcheck source=/dev/null
. "${SCENARIO_ENV}"

: "${TARGET_HOST:?設定値 TARGET_HOST が無い}"
: "${BACKUP_DIR:?設定値 BACKUP_DIR が無い}"

ng=0
check() {  # check "説明" コマンド...  — 期待どおりなら OK、違えば NG を数える
  local desc="$1"; shift
  if "$@" >/dev/null 2>&1; then
    printf 'OK  %s\n' "${desc}"
  else
    printf 'NG  %s\n' "${desc}"
    ng=$((ng + 1))
  fi
}

# ---- 前処理（事前条件の確認）。1つでも NG なら主処理に進まない ----
check "対象ホストに到達できる"            ping -c 1 -W 2 "${TARGET_HOST}"
check "バックアップ先が存在する"          test -d "${BACKUP_DIR}"
check "バックアップ先に書き込める"        test -w "${BACKUP_DIR}"
if [ "${ng}" -ne 0 ]; then
  printf '事前条件 NG が %d 件。主処理を実行しない。シナリオの分岐表に従う。\n' "${ng}" >&2
  exit 10
fi

# ---- 主処理 ----
printf '主処理を実行する: %s のバックアップを %s へ（y で続行）: ' "${TARGET_HOST}" "${BACKUP_DIR}"
read -r answer
[ "${answer}" = "y" ] || { echo "中止した" >&2; exit 11; }

# [ここに主処理のコマンド。1行ごとに失敗したら止める]
# 例: ssh "${TARGET_HOST}" 'tar czf - /etc/app' > "${BACKUP_DIR}/app-etc.tgz" || exit 12

# ---- 後処理（完了条件の確認）----
ng=0
check "バックアップファイルが存在し空でない"  test -s "${BACKUP_DIR}/app-etc.tgz"
check "アーカイブとして読める"                tar tzf "${BACKUP_DIR}/app-etc.tgz"
if [ "${ng}" -ne 0 ]; then
  printf '完了条件 NG が %d 件。このタスクの「戻し方」へ。\n' "${ng}" >&2
  exit 20
fi
echo "T01 完了"
exit 0
```

## 決めごと

- **`source` しない。必ず `bash tasks/T01-....sh` で新しいプロセスとして実行する。** タスクの変数が
  作業者のシェルに残らない（発表の「ターミナルを閉じる」と同じ目的）
- **設定値は1つのファイルに集め、作業の前日までに埋める**（`scenario.env`。値の指定と実行を分ける）。
  タスクのスクリプトに値を直書きしない。認証情報はこのファイルにも書かない
- **終了コードを揃える** — `0` 完了、`1` 設定値が無い（何も変更していない）、`10` 事前条件 NG（何も変更していない）、`11` 作業者が中止、
  `12〜19` 主処理の失敗（**途中まで変更済み**。戻し方へ）、`20` 完了条件 NG（戻し方へ）。
  シナリオの分岐表はこの終了コードで書ける
- **取り消せない主処理の前には、必ず対話の確認（`read`）を置く**
- 手順書（Markdown）がタスクの正本で、スクリプトはその実行部。片方を直したら両方を同じ変更で直す。
  Markdown の主処理にはスクリプトと同じコマンドを書く（スクリプトが無くても手で実施できるように）

## 検査（書いたら必ず）

- `bash -n tasks/*.sh` と `shellcheck tasks/*.sh`（入っていれば）を通す
- **本番以外で**、事前条件を1つわざと満たさない状態で実行し、終了コード `10` で止まり何も変更されないことを
  人が確かめる（Claude は実行しない — manual-write の中核ルール1）
