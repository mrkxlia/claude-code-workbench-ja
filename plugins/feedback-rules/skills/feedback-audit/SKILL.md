# feedback-audit — ルールの棚卸し

ルールは増える一方です。**誤検知するルールと形骸化したルールを放置すると、仕組み全体が
信用されなくなり、警告が読み飛ばされる**ようになります。定期的に捨てる・直すためのスキルです。

## Step 1 — 集計を取る

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/hooks/feedback_rules.py" stats
python3 "${CLAUDE_PLUGIN_ROOT}/hooks/feedback_rules.py" doctor
```

`stats` はルール別の総発火数・直近7日の発火数・severity 内訳・最終発火時刻に加えて、
昇格候補（暫定のまま多発）・形骸化候補（発火ゼロ）・未確定の指摘候補の件数を出します。

## Step 2 — 仕分けを委譲する（ルールが10件以上のとき）

`feedback-auditor` サブエージェントに Task ツールで委譲します。エンジンの絶対パスと
ルール置き場のパスを**渡し切って**ください（サブエージェントは呼び出し側の文脈を持ちません）。
集計ログでメインの文脈を汚さないための委譲です。ルールが数件なら直接読んで構いません。

## Step 3 — 承認を得る

提案は**必ず人間に見せてから**反映します。とくに次は勝手にやらない:

- **count の引き上げ** — count は「人間が指摘した回数」です。発火回数から自動で上げるのは
  この仕組みの前提を壊します（フックが自分でルールを重くできてしまう）。必ず確認します。
- **ルールファイルの削除** — なぜそのルールがあったのかの記録が消えます。
  まず `enabled: false` か `expires` を提案します。

## Step 4 — 反映する

承認された変更だけを frontmatter に適用します。無効化する場合は、本文の末尾に
「いつ・なぜ無効化したか」を1行残します（同じ議論を繰り返さないため）。

## Step 5 — .claude/rules/ へ同期する（任意）

count 3 以上かつ `paths` を持つルールは、本体ネイティブの `.claude/rules/` へ書き出せます。
本体は `paths` frontmatter を見て**対象ファイルに触るときだけ**そのルールを読むので、
毎ターンの注入予算を消費しません。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/hooks/feedback_rules.py" sync-rules --dry-run
python3 "${CLAUDE_PLUGIN_ROOT}/hooks/feedback_rules.py" sync-rules
```

生成物には `generated-by: feedback-rules` のマーカーが入り、元ルールが消えたり条件から
外れたら次回の同期で削除されます。**生成された `.claude/rules/feedback-*.md` を直接編集しない**
（次の同期で上書きされます）。編集するのは元のルールファイルです。

## Step 6 — 報告する

- 何件を昇格・無効化・修正したか、それぞれ severity がどう変わるか
- 触らなかったが気になるもの（次回の観察対象）
- 未確定の指摘候補が残っているなら、`/feedback-rule` で処理するよう促す

## 棚卸しの目安

| 症状 | 打ち手 |
|---|---|
| 警告が多すぎて読み飛ばしている | 誤検知しているルールを `unless` で絞る。それでも駄目なら `severity: warn` に固定 |
| ルールが増えて注入が重い | `paths` を付けて `.claude/rules/` へ逃がす。count 1〜2 のものは元々注入されない |
| 同じ違反が deny なのに繰り返される | モデルが別の書き方で迂回している。`when` をツール族単位に広げる |
| 発火ゼロのルールばかり | 正規表現が間違っている可能性。`doctor` の備考欄を確認する |
