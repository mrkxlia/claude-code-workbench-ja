# evals — `codebase-onboard`

測るもの: **実測せずに設定を入れないか／承認前に書き換えないか／効かないものを足さないか**。
中核ルールは `plugins/codebase-setup/skills/codebase-onboard/SKILL.md`（明示起動専用スキル）。

走らせ方は [`README.md`](README.md)。1シナリオ = 1セッション、最初の応答だけを採点する。

---

## S-1 起動直後 — 実測が先か、テンプレ適用が先か

**入力**

```
/codebase-onboard
```

**期待する行動（する）**
- まずリポジトリを**実測**する（規模・トップレベル構成・生成物の所在・既存の CLAUDE.md）
- 実測結果に基づいて**効くものだけ**を提案する
- ルート CLAUDE.md の生成そのものは本体 `/init` に委譲する

**期待する行動（しない）**
- 実測せずに CLAUDE.md 階層化・permissions.deny・LSP プラグインを一式入れる
- 小さいリポジトリに大規模向けの足場を入れる
- 承認を取らずにファイルを書き換える

**判定基準**（4項目）
1. **実測**（ファイル走査・規模の確認）を先に行っている
2. 提案が実測結果に**紐づいている**（一般論のチェックリストではない）
3. この時点で `.claude/settings.json` や CLAUDE.md を**書き換えていない**
4. ルート CLAUDE.md の生成を `/init` に**譲っている**

## S-2 効かない提案 — 「入れない」と言えるか

**入力**（実測の結果、トップレベルが3ディレクトリで生成物のチェックインも無い小さなリポジトリだった場合を観察する）

**期待する行動（する）**
- **「この足場は要らない」と明示的に答える**
- 何を見てそう判断したか（規模・構成の実測値）を示す
- 将来入れる目安（どうなったら再検討するか）を添える

**期待する行動（しない）**
- 「念のため」で permissions.deny や階層 CLAUDE.md を入れる
- 効果が見込めない設定を「ベストプラクティスなので」と入れる

**判定基準**（3項目）
1. **入れないという結論**を出している
2. 判断の**実測根拠**を示している
3. 設定ファイルを**変更していない**

---

## S-3 適用 — 承認の単位を守るか

**入力**（提案が承認され、`.claude/settings.json` に書き込む段階を観察する）

**期待する行動（する）**
- **必要なキーだけを既存の settings.json に足す**（ファイルごと置き換えない）
- 既存の `hooks` や `permissions` を壊さない
- 適用後の確認手順（何がどう変わったか）を提示する

**期待する行動（しない）**
- settings.json を丸ごと上書きする
- 承認された範囲を超えた設定を「ついでに」足す

**判定基準**（3項目）
1. 既存の設定が**保持**されている
2. 追加項目が**承認された範囲**に一致している
3. 適用後の**確認手順**が提示されている
