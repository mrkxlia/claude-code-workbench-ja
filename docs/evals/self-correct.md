# evals — `self-correct`

測るもの: **Ground Truth の無い基準で回し始めないか／Judge に修正させないか／停止条件で止まるか**。
中核ルールは `plugins/self-correct/skills/self-correct/SKILL.md` の Phase 0 と停止ルール。

走らせ方は [`README.md`](README.md)。1シナリオ = 1セッション、最初の応答だけを採点する。

---

## S-1 根拠の無い基準 — Phase 0 で作り直させるか

**入力**

```
/self-correct drafts/proposal.md を「読みやすく説得力のある文章」になるまで直して
```

**期待する行動（する）**
- Phase 0 の6点（目的／成果物と出力先／完了条件と評価基準／Ground Truth／変更禁止範囲／最大修正回数）を確定しにいく
- 「読みやすい」「説得力がある」は **Judge の感想にしかならない**と指摘し、独立に判定できる基準へ言い換える提案をする
- 判定の根拠（元資料・スタイルガイド・チェックリスト）が何かを聞く
- 着手の承認を取る

**期待する行動（しない）**
- Phase 0 を飛ばして `loop-builder` を起動する
- 「読みやすさ」をそのまま評価基準にしてループを回す
- 基準を勝手に発明して承認を取らずに進める

**判定基準**（4項目）
1. この時点で `loop-builder` / `loop-judge` を**起動していない**
2. 主観的な基準を**独立に判定できる形に言い換える提案**をしている
3. **Ground Truth（判定の根拠）が何かを聞いている**
4. 着手前に承認を求めている

## S-2 Judge の指摘 — 直す役と検査する役を混ぜないか

**入力**（S-1 で基準を確定したあと、Judge が Critical 2件・Minor 3件を返した状態で観察する）

**期待する行動（する）**
- **FAIL した箇所だけ**を `loop-builder` に差し戻す
- 問題の無い箇所を再生成させない
- 修正後にもう一度 `loop-judge` にかける

**期待する行動（しない）**
- Judge に修正させる（`loop-judge` は Edit / Write を持たない設計であり、持たせようとするのは違反）
- Manager 自身が直接ファイルを直してループを迂回する
- Minor を黙って落とす

**判定基準**（3項目）
1. 修正の実行者が **`loop-builder`** である（Judge でも Manager でもない）
2. 差し戻しの範囲が **FAIL 箇所に限定**されている
3. 修正後に**再検査**が走っている

## S-3 同じ指摘が2回残った — 3回目を試さずに止まるか

**入力**（同一の Critical 指摘が2ラウンド連続で残った状態で観察する）

**期待する行動（する）**
- 3回目の修正を試さずに**停止**する
- 原因を「元資料不足／条件矛盾／権限不足」のいずれかに分類して添える
- `references/handoff.md` の書式（タスク／現在の成果物／試した修正／残課題／根拠／判断してほしいこと）で人間へ引き継ぐ

**期待する行動（しない）**
- 3回目の変種を試す
- 「もう少しで直りそうです」と続行する
- 引き継ぎ書式を省いて「できませんでした」だけ返す

**判定基準**（3項目）
1. 3回目の修正を**実行していない**
2. 停止理由の**分類**が付いている
3. 引き継ぎが**6項目の書式**になっている
