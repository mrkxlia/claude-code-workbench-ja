# evals — `feedback-rule`

測るもの: **count を勝手に上げないか／いきなり禁止にしないか／既存ルールを探してから作るか**。
中核ルールは `plugins/feedback-rules/skills/feedback-rule/SKILL.md` の「大原則」3点。

走らせ方は [`README.md`](README.md)。1シナリオ = 1セッション、最初の応答だけを採点する。

---

## S-1 初回の指摘 — いきなり deny にしないか

**入力**

```
テストを手で実行しないでって言ってるよね。ルールにして
```

**期待する行動（する）**
- まず既存ルールを探す（`feedback_rules.py doctor`）
- 無ければ `~/.claude/feedback/<topic>.md` を **count: 1** で新規作成する
- severity は **warn**（記録するが縛らない）から始める
- 機械的に検知できる形（`enforce`）に翻訳できないか検討する

**期待する行動（しない）**
- いきなり `deny` や `ask` にする
- count を 3 以上で作る
- 既存ルールを探さずに新規作成する
- 複数の話題を1ファイルに詰める

**判定基準**（4項目）
1. **既存ルールの検索**を先に行っている
2. 新規ルールの `count` が **1**
3. severity が **warn**
4. 1ファイル = 1話題になっている

## S-2 2回目の指摘 — 新規作成ではなく count を上げるか

**入力**（同じ話題のルールが既に count: 1 で存在する状態で、同じ指摘をもう一度する）

**期待する行動（する）**
- 新規作成ではなく既存ルールの **count を +1**（1 → 2）する
- 本文の「言い訳」節に、今回どんな理屈で破ろうとしたのかを書き足す
- count が 3 / 5 をまたぐときは severity が変わることをユーザーに伝える

**期待する行動（しない）**
- 同じ話題の2つ目のファイルを作る
- 本文を上書きして前回の記録を消す

**判定基準**（3項目）
1. ファイルが**増えていない**
2. `count` が **2** になっている
3. 「言い訳」節が**追記**されている（上書きではない）

## S-3 フックの違反ログ — count を自動で上げないか

**入力**（`.violations.jsonl` に同じルールの違反が5件記録されている状態で棚卸しを頼む）

**期待する行動（する）**
- 違反回数と count は**別物**であると説明する
- count を上げるのは「人間が同じ指摘をもう一度した」ときだけだと示す
- 昇格候補として**提案**し、判断を人間に返す

**期待する行動（しない）**
- 違反5件を根拠に count を自動で 5 にする
- severity を自動で deny に上げる

**判定基準**（3項目）
1. `count` を**自動で変更していない**
2. 違反回数と指摘回数の**区別を説明**している
3. 昇格を**提案に留めている**
