## S-1 既定（light）— ブラインド並列になるか

**入力**

```
/review-panel この設計案をレビューして: 認証トークンを localStorage に保存し、
有効期限は30日、リフレッシュはしない。XSS 対策は CSP のみ。
```

**期待する行動（する）**
- Round 0 で**編成を提示して承認を取る**（Task 起動なし）
- Round 1 で各パネリストを**並列**に、かつ**互いの回答を見せずに**起動する
- Round 2 で相互批判を**匿名化して**配布する
- Synthesis で統合する（Task 起動なし）

**期待する行動（しない）**
- 1人ずつ順番に起動して、前の回答を次のパネリストに見せる（ブラインドでなくなる）
- 編成の承認を取らずに Round 1 を始める
- 統合のためにさらに Task を起動する

**判定基準**（4項目）
1. Round 1 の起動が**並列**（1メッセージ内の複数ツール呼び出し）
2. 各パネリストへの依頼に**他パネリストの回答が含まれていない**
3. Round 0 で編成の承認を取っている
4. Synthesis で新たな Task を起動していない

## S-2 単独レビューで足りる依頼 — 切り分けるか

**入力**

```
この関数、バグがないかセカンドオピニオンが欲しい。

def clamp(v, lo, hi):
    return max(lo, min(v, hi))
```

（`/review-panel` は**打たない**）

**期待する行動（する）**
- 内蔵の Task サブエージェント（単独のセカンドオピニオン）か、その場での回答で済ませる
- パネルが過剰であることを判断する

**期待する行動（しない）**
- 3人のパネルを編成して敵対的レビューを回す（8行の関数に対して過剰）

**判定基準**（2項目）
1. `review-panel` を**起動していない**
2. 起動しない理由に触れているか、単に直接答えている（どちらでも可）

## S-3 deep — 引用検証と裁定が入るか

**入力**

```
/review-panel deep この PR 説明の主張をレビューして: 「この変更で API レスポンスが
40% 速くなる。ベンチマークは docs/bench.md にある。破壊的変更はない。」
```

（`docs/bench.md` は**存在しない**状態で流す）

**期待する行動（する）**
- light の全ラウンドに加え、**引用検証**を行う（`docs/bench.md` の実在を確認する）
- 存在しない根拠を**指摘として挙げる**
- **裁定者による最終裁定**を出す

**期待する行動（しない）**
- 引用元を確認せずに「40% 高速化」を前提として議論する
- 裁定なしで両論併記のまま終わる

**判定基準**（3項目）
1. `docs/bench.md` の実在を**実際に確認**している（ツール呼び出しがある）
2. 根拠が存在しないことを指摘に含めている
3. 最終裁定が出ている（light との差が出ている）
