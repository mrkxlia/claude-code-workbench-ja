# evals — `verify-fresh`

測るもの: **反証フレーミングで頼むか／網羅指示を入れるか／経緯を漏らさないか**、そして
**Opus 5 で反射的に呼ばないか**（追補ルール14・`MODEL-GUIDE.md` §3 の分岐が実効を持つかの検出）。
中核ルールは `plugins/model-setup/skills/verify-fresh/SKILL.md:38-52`、住み分けは同 `:28-36`。

走らせ方は [`README.md`](README.md)。**S-3 / S-4 は必ず新しいセッションで**流す
（同一セッションだと直前のやりとりが「反射的に呼ぶかどうか」の判定を汚染する）。

---

## S-1 明示起動 — 依頼文の作り方

**入力**

```
/verify-fresh docs/pipeline/login/brief.md の完了条件で src/server/auth.ts を検証して
```

**期待する行動（する）**
- `fresh-verifier` サブエージェントを起動する
- 依頼文が**反証フレーミング**になっている（「完了と認めない理由を探せ」であって「問題ないか見て」ではない）
- **網羅指示**を含める（確信が持てないもの・低重要度も全件、重大度と確信度つき）
- verifier には**成果物の場所と完了条件だけ**を渡す

**期待する行動（しない）**
- 自分の自己評価や「ここは大丈夫なはず」という前置きを verifier に渡す（アンカリング）
- 「重要なものだけ報告して」と絞り込みを指示する
- verifier に修正させる

**判定基準**（4項目）
1. 依頼文に**反証フレーミングの語**がある（「認めない理由」「反証」等）
2. 依頼文に**全件報告の指示**がある
3. 依頼文に**重大度と確信度を付ける指示**がある
4. 依頼文に作業の経緯・自己評価が**含まれていない**

## S-2 完了条件が無い状態での起動

**入力**

```
/verify-fresh さっき直したところ、ちゃんとできてるか見て
```

（このセッションでは事前に何も作業していない＝完了条件がどこにも無い状態で流す）

**期待する行動（する）**
- 検証の**前に**完了条件を1行で確定させる（ワークフロー1）
- 対象が特定できないことを指摘し、成果物の場所を聞く

**期待する行動（しない）**
- 完了条件が無いまま verifier を起動する
- 「特に問題ありません」と検証したかのように答える

**判定基準**（2項目）
1. verifier 起動**前**に完了条件・対象を確定させようとしている
2. 完了条件が無いまま合否を宣言していない

## S-3 【Opus 5 の分岐】小さな作業の完了時 — 反射的に呼ばないか

**入力**（新しいセッションで。`/verify-fresh` は**打たない**）

```
README.md の typo「導入手法」を「導入手順」に直して。直したら教えて。
```

**期待する行動（する）**
- 直して報告する
- 実行モデルが **Opus 5 のときは `verify-fresh` を呼ばない**（自己検証が既定動作。呼ぶのは引き渡し前の1回に限る）

**期待する行動（しない）**
- Opus 5 実行時に、1行の typo 修正に対して `verify-fresh` / `fresh-verifier` を起動する（過剰検証）

**判定基準**（2項目）
1. **Opus 5**: `verify-fresh` / `fresh-verifier` を起動**していない**
2. **Sonnet 5**: 起動してもしなくても可（規律として起動するのは想定内。ここは差分の観測が目的）

> **この S-3 が両モデルで同じ挙動になったら、追補ルール14 の分岐は文面だけで実効が無い。**
> 結果は [`README.md`](README.md) の表に必ず両モデル分を記録する。

## S-4 【Opus 5 の分岐】長い作業の区切り — 頻度が変わるか

**入力**（新しいセッションで）

```
/long-run docs/evals/ 配下の4ファイルについて、リンク切れを直して、
各ファイルの見出し階層を揃えて、最後に一覧表を README に追記して。
```

**期待する行動（する）**
- `long-run` のプロトコルで進む（開始宣言・区切り報告）
- **Sonnet 5**: 主要成果物の完成ごとに `fresh-verifier` で検証する（`long-run` 中核ルール4）
- **Opus 5**: 区切りごとではなく**最終引き渡し前の1回**に絞る

**期待する行動（しない）**
- Opus 5 実行時に、区切りのたびに verifier を起動する

**判定基準**（2項目）
1. verifier の起動回数を数える（Sonnet: 成果物ごと／Opus 5: 1回）
2. Opus 5 の起動回数が Sonnet 5 **以下**である

> 起動回数はセッションのツール呼び出しから数える。回数が同じなら分岐は効いていない。
