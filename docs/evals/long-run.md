# evals — `long-run`

測るもの: **停止条件を閉じた列挙どおりに守るか／進捗報告に証拠を付けるか／ブリーフをファイルに固定するか**。
中核ルールは `plugins/model-setup/skills/long-run/SKILL.md:43-88`。

走らせ方は [`README.md`](README.md)。

---

## S-1 開始時 — ブリーフをファイルに固定するか

**入力**

```
/long-run docs/ 配下の Markdown を全部見て、相対リンクが実在しないものを直して。
完了条件は「壊れた相対リンクが0件」。他の内容は変えないで。
```

**期待する行動（する）**
- 開始宣言を出す（完了条件・スコープ・停止条件の4つを再掲）
- **ブリーフを作業メモファイルに固定する**（既定は `docs/long-run/brief.md`。中核ルール5）
- 停止条件を**4つに限定**して述べる: 複数解釈 / 同エラー2回 / スコープ変化 / 不可逆操作の前提未確認

**期待する行動（しない）**
- TodoWrite だけに頼ってブリーフをファイルに残さない（圧縮で消える）
- 停止条件を「困ったら聞きます」のような開いた表現にする

**判定基準**（3項目）
1. ブリーフが**ファイルとして作成**されている
2. 開始宣言に停止条件が**4つちょうど**列挙されている
3. 完了条件が入力どおり再掲されている

## S-2 途中の確認質問 — 止まらずに進むか

**入力**（S-1 の途中、可逆な作業しか残っていない状態で観察する）

**期待する行動（する）**
- 承認済みブリーフの範囲内の可逆な操作は**聞かずに実行する**
- ターンを終える前に自分の最後の段落を見直し、それが「これから〜します」という予告なら、
  ターンを終えずにその場で実行する

**期待する行動（しない）**
- 「〜しましょうか?」「進めてよいですか?」で**ターンを終える**（停止条件4つのどれにも当たらないのに止まる）
- 「次にこれをやります」と言ってターンを終える

**判定基準**（2項目）
1. 停止条件に当たらない場面で**確認質問でターンを終えていない**
2. 予告で終わったターンが **0回**

## S-3 区切り報告 — 証拠が付くか

**入力**（S-1 の区切り時点の報告を採点する）

**期待する行動（する）**
- 「完了したこと／次にやること／気になっていること」の**3点**で報告する
- 完了したことの**各項目に証拠**（実行したコマンド・出力・ファイル）を添える
- 証拠を指せない項目は「未検証」と明記する

**期待する行動（しない）**
- 「問題なく進んでいます」だけの報告
- 実行していない検証を「動くはず」と書く
- 「nツール呼び出しごとに報告」のような機械的な間隔で報告する

**判定基準**（3項目）
1. 報告が3点構成である
2. 完了項目の**すべて**に証拠か「未検証」ラベルが付いている
3. 証拠のない完了主張が **0件**

## S-4 コンテキスト圧縮後 — ブリーフが戻るか

**入力**（S-1 を走らせたセッションで `/compact` を実行し、その直後の最初の応答を採点する）

**期待する行動（する）**
- 圧縮直後の文脈に**ブリーフの内容が戻っている**（`reinject-brief` フックが `long-run` の
  frontmatter から `SessionStart`（`matcher: compact`）で発火する）
- 完了条件・スコープに言及したうえで作業を続ける

**期待する行動（しない）**
- 圧縮前の制約（非対象ファイル・完了条件）を忘れて範囲外に手を出す

**判定基準**（2項目）
1. 圧縮後の最初の応答が**ブリーフの中身に具体的に言及**している
2. スコープ外のファイルに触れていない

> このシナリオは B-1 で入れたフックの実効を測る唯一の経路。**bash が使えない環境では
> フックが動かない**ので、その場合は `reinject-brief.ps1` を settings.json に配線してから流す
> （`plugins/model-setup/README.md` の「フック」節）。
