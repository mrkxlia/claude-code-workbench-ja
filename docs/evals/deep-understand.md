# evals — `deep-understand`

測るもの: **講義から始めないか／クイズで実証するか／「わかりました」で通さないか**。
中核ルールは `plugins/learning-coach/skills/deep-understand/SKILL.md` の中核ルール1・5・8 と合格ライン。

走らせ方は [`README.md`](README.md)。1シナリオ = 1セッション、最初の応答だけを採点する。

---

## S-1 起動直後 — 診断が先か、講義が先か

**入力**

```
/deep-understand さっきの変更を理解したい
```

**期待する行動（する）**
- 3層（問題／解決／広い文脈）のチェックリストを**作って提示**する（合計5〜9項目）
- 「この項目立てで進めていいか、抜けている論点はないか」を確認する
- **ユーザー自身に現在の理解を述べさせる**

**期待する行動（しない）**
- チェックリストを出さずに解説を始める
- 変更内容の長い説明を一度に出す
- ユーザーの理解を聞かずに教える順番を決める

**判定基準**（4項目）
1. チェックリストを**提示**している
2. 項目数が **5〜9**
3. **ユーザーに現在の理解を述べさせる**問いかけがある
4. この時点で本題の解説を始めていない

## S-2 クイズ — 答えを先に見せないか

**入力**（項目1つの説明が終わり、理解を試す段階を観察する）

**期待する行動（する）**
- `AskUserQuestion` を使い、**設問をまとめて出す**（最大4問）
- 全問の回答が返るまで**どの問題の答えも明かさない**
- 正解の選択肢の位置を問ごとに散らす
- 誤答の選択肢にも、もっともらしい理由を同じ密度で書く

**期待する行動（しない）**
- 会話文で「分かりましたか？」と聞く
- 設問と同時に答えを見せる
- 1問ずつ出して都度答え合わせする（後の設問のヒントになる）
- 常に最初の選択肢や一番長い選択肢を正解にする

**判定基準**（4項目）
1. `AskUserQuestion` を使っている
2. 回答前に**答えを明かしていない**
3. 正解位置が**固定されていない**
4. 誤答が「明らかな当て馬」になっていない

---

## S-3 曖昧な回答 — 「だいたい合っている」で通さないか

**入力**（ユーザーが「なんとなく分かりました」とだけ答えた状態を観察する）

**期待する行動（する）**
- 合格ライン3点（再説明／転移／予測）のうち**欠けたものを狙った設問**を追加で出す
- チェックを `[x]` にせず、`[~]`（説明済み・未実証）のままにする
- 別角度で説明し直す（同じ説明を繰り返さない）

**期待する行動（しない）**
- 「わかりました」を実証とみなして `[x]` にする
- 次の項目へ進む
- チェックリストからその項目を静かに落とす

**判定基準**（3項目）
1. 当該項目が **`[x]` になっていない**
2. **追加の設問**が出ている
3. 説明の繰り返しではなく**角度を変えて**いる
