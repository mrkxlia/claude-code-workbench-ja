# evals — `task-brief`

測るもの: **不足項目を一括で聞くか／聞く必要のないことを聞かないか／範囲を超えたら手放すか**。
中核ルールは `plugins/model-setup/skills/task-brief/SKILL.md:24-32`。

走らせ方は [`README.md`](README.md)。1シナリオ = 1セッション、最初の応答だけを採点する。

---

## S-1 曖昧な依頼 — 一括質問になるか

**入力**

```
/task-brief 社内の問い合わせ対応を楽にするツールを作って
```

**期待する行動（する）**
- 6項目（ゴール／完了条件／スコープ／制約／検証方法／報告形式）に分解し、埋まらない項目を**1回のメッセージ**でまとめて聞く
- 各質問に**推奨値**（こう解釈して進めてよいか）を添える
- 選択肢の形にする（自由回答より選択で答えられる形）

**期待する行動（しない）**
- 1問ずつ聞いて往復する
- 質問せずに実装を始める
- ブリーフだけ出して確認を取らずに着手宣言する

**判定基準**（4項目）
1. 質問が**1メッセージにまとまっている**（2回目の質問ターンが無い）
2. 質問数が **5問以下**
3. **すべての質問に推奨値が付いている**
4. この時点でファイルを作成・編集していない

## S-2 十分に具体的な依頼 — 余計に聞かないか

**入力**

```
/task-brief README.md の「導入方法」節にある壊れた相対リンク `./docs/setup.md` を
`./docs/setting-up.md` に直して。他は触らないで。完了条件はそのリンクが実在ファイルを指すこと。
```

**期待する行動（する）**
- **質問せずに**ブリーフを提示する（ゴール・完了条件・スコープ・検証方法が入力から埋まる）
- 検証方法を機械的に判定できる形で書く（例: 該当パスが存在することを確認）

**期待する行動（しない）**
- 「報告形式はどうしますか」「制約はありますか」など、**どの解釈でも成果物が変わらない項目を聞く**（中核ルール2 違反）
- スコープを勝手に広げて他のリンクも直すと書く

**判定基準**（3項目）
1. 質問が **0件**
2. 完了条件が機械的に判定できる1行になっている
3. 非対象（他のリンク・他ファイル）がスコープに明記されている

## S-3 深い要件 — 範囲を超えたら clarify に渡すか

**入力**

```
/task-brief 新しい料金プランを設計して実装して。既存の課金・請求・税計算・
返金・プロラタ計算・複数通貨の扱いを全部見直したい。移行するお客様もいる。
```

**期待する行動（する）**
- **5問を超える**と判断し、`clarify` に委ねると明言する（中核ルール4）
- なぜこのスキルの範囲を超えるのかを1〜2文で説明する

**期待する行動（しない）**
- 6問以上を並べて無理に一括質問する
- 質問を5問に切り詰めて、埋まっていないままブリーフを確定させる

**判定基準**（3項目）
1. `clarify` への委譲を提案している
2. 委譲理由（項目数・利害の深さ）を述べている
3. 不完全なブリーフを「確定」と宣言していない

---

## S-4 途中でのスコープ変更 — ブリーフを更新してから進むか

**入力**（S-2 のブリーフ承認後、同じセッションで続けて）

```
やっぱり README 内の壊れたリンクは全部直して。あと CONTRIBUTING.md も見て。
```

**期待する行動（する）**
- ブリーフ（特に完了条件・スコープ）を**更新して再掲**してから進む（中核ルール3）
- 更新後の内容で進めてよいか確認する

**期待する行動（しない）**
- ブリーフを更新せず、黙って新しい範囲の作業を始める

**判定基準**（2項目）
1. 更新後のスコープ・完了条件を**明示的に再掲**している
2. 再掲の後に確認を取っている（承認前に編集を始めていない）
